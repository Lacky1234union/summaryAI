# Архитектура Summuraze

## Что строим

Локальный конвейер: **аудио/видео записи** (созвон, лекция, встреча, семинар) → **транскрипт с
таймкодами** (STT локально, на CPU) → **структурированное саммари** (LLM по API или локально) →
**Markdown-документ** со ссылками на таймкоды.

Формат работы — CLI и пакетная обработка, не realtime. Один ноутбук, без GPU, без Docker-зоопарка.

---

## Железо, на котором это должно работать (замерено 2026-09-23)

| | |
|---|---|
| CPU | AMD Ryzen 7 5700U — 8 ядер / 16 потоков, Zen2, мобильный 15 Вт |
| GPU | нет дискретной; встроенная Radeon Vega (общая память) |
| RAM | 14 ГБ всего, свободно ~5.6 ГБ при обычной загрузке |
| Диск | 196 ГБ свободно |
| Аудио | PipeWire (`pw-record`, `parecord`) — есть захват монитора вывода |
| Есть | `ffmpeg` n9.0.1, `uv`, Python 3.14 (проект пойдёт на 3.12) |
| Нет | `ollama`, CUDA/ROCm. `llama-server` — сборка Vulkan в `~/.local/opt` (#19); Vulkan видит iGPU (RADV RENOIR) |

**Следствия, которые определяют весь дизайн:**

1. **STT — только CPU-инференс с квантизацией.** Никакого `openai-whisper` на torch: только
   CTranslate2 (`faster-whisper`) или `whisper.cpp` с int8. Модель выбирается замером (этап 1), а
   не по популярности.
2. **Realtime не обещаем.** Цель — RTF ≤ 0.5 (час записи за ≤ 30 мин). Транскрибация идёт фоном.
3. **Одновременно STT и локальная LLM в память не влезут.** 14 ГБ всего, ~9 ГБ уже занято системой.
   Конвейер строго последовательный: модель стадии выгружается до загрузки следующей.
4. **Дорогая стадия — ASR.** Значит артефакты стадий кэшируются на диск: правка промпта саммари
   не должна перезапускать 25 минут транскрибации. Это архитектурное требование, не оптимизация.
5. **Два трека при записи созвона дают сепарацию спикеров бесплатно** — микрофон (я) и монитор
   вывода (они) пишутся раздельно. Diarization-модель нужна только для «много людей в одной
   комнате».

## Конвейер

```
файл / запись
     │
 1. ingest      ffmpeg → wav 16 kHz mono PCM s16; метаданные (длительность, каналы, источник)
     │
 2. vad         Silero VAD → интервалы речи
     │          (отсекает тишину и музыку: −20…40 % времени ASR и главный источник
     │           галлюцинаций Whisper — циклы «Спасибо за просмотр» на тишине)
     │
 3. asr         ASRProvider → сегменты + word-level таймкоды + logprob
     │
 4. diarize     (опционально) SpeakerSource: раздельные треки ИЛИ diarization-модель
     │
 5. transcript  сборка: сегменты + спикеры → Transcript (кэшируется, это ценный артефакт сам по себе)
     │
 6. outline     только для длинных записей: окна → карта разделов с таймкодами
     │
 7. summarize   LLMProvider + профиль (созвон / лекция / встреча / семинар) → структура
     │
 8. verify      каждое утверждение сверяется с транскриптом по своему таймкоду: та же модель,
     │          тот же префикс; неподтверждённое помечается в заметке, а не удаляется (#22)
     │
 9. render      Markdown (основной вывод) + SRT/VTT + JSON
```

Каждая стадия — чистая функция «артефакт → артефакт». Ключ кэша =
`sha256(входной артефакт + версия стадии + значимые параметры)`. Повторный запуск с теми же
параметрами читает с диска.

## Контракты

Единый источник истины для типов — `summuraze/types.py`. Провайдеры не импортируют друг друга.

```python
class Interval(BaseModel):
    start: float          # секунды от начала записи
    end: float

class Word(Interval):
    text: str
    prob: float           # уверенность — вход для verify и для подсветки сомнительных мест

class Segment(Interval):
    text: str
    speaker: str | None
    words: list[Word]
    avg_logprob: float
    no_speech_prob: float

class Transcript(BaseModel):
    source: Path
    duration: float
    language: str
    model: str            # чем расшифровано — попадает в вывод, влияет на доверие
    segments: list[Segment]

class ASRProvider(Protocol):
    name: str
    def transcribe(self, audio: Path, *, language: str | None,
                   speech: list[Interval] | None) -> Transcript: ...

class LLMProvider(Protocol):
    name: str
    context_window: int
    def complete(self, *, system: str, user: str, max_tokens: int,
                 cache_prefix: bool = False) -> LLMResult: ...   # LLMResult: text + usage + cost

class SpeakerSource(Protocol):
    def turns(self, audio: Path) -> list[SpeakerTurn]: ...
```

Правило: **провайдер за протоколом + фабрика по конфигу.** Вендорские библиотеки
(`faster_whisper`, `anthropic`, `pyannote`) импортируются только внутри своего модуля-адаптера,
и импорт ленивый — чтобы CLI стартовал за 200 мс, а не за 6 секунд на загрузке torch.

## Провайдер саммаризации: один адаптер, два пути

Требование — **переключаться между локальной моделью и API одним флагом**. Это получается почти
бесплатно, потому что DeepSeek, OpenRouter, Yandex AI Studio **и** локальные llama.cpp / Ollama
говорят по одному и тому же OpenAI-совместимому протоколу. Значит это не два провайдера, а
**один адаптер** `openai_compat.py`, где переключение — это `base_url` + `model` + `api_key`:

| Режим | `base_url` | `model` |
|---|---|---|
| API, дефолт | `https://api.deepseek.com/v1` | `deepseek-flash` |
| API, сложные записи | `https://api.deepseek.com/v1` | `deepseek-v4-pro` |
| Локально, `--local` | `http://127.0.0.1:<свободный порт>/v1` — сервер поднимает сам summuraze | `SUMMURAZE_LOCAL_LLM_MODEL` (gguf) |
| Другой API | OpenRouter / Yandex AI Studio | их ID |

`anthropic_llm.py` (Claude) — отдельный опциональный адаптер: другой формат запроса, отдельный код.
Заводим, только если понадобится.

### DeepSeek — параметры на 2026-09-23 (сверено с api-docs.deepseek.com)

| Модель | Контекст | Макс. выход | Вход (miss) | Вход (hit) | Выход |
|---|---|---|---|---|---|
| `deepseek-flash` (V4.1-Flash) | 1M | 384K | $0.15 / $0.30 | $0.003 / $0.006 | $0.60 / $1.20 |
| `deepseek-v4-pro` (V4-Pro-0813) | 1M | 384K | $0.66 / $1.32 | $0.022 / $0.044 | $1.98 / $3.96 |

Две цены — off-peak / peak. Peak = 01:00–04:00 и 06:00–10:00 UTC, пн–пт; off-peak вдвое дешевле и
покрывает большую часть недели.

**Стоимость двухчасовой лекции на `deepseek-flash`:** ~40k входных ($0.006) + ~4k выходных
($0.0024) ≈ **$0.01 за документ**. Пакетную обработку архива записей имеет смысл гонять в off-peak.

**Важно:** алиас `deepseek-chat` retired 24.07.2026 — в коде его не писать. Актуальные ID сверять
в момент реализации, а не по памяти: провайдер меняет модельный ряд чаще, чем мы правим доки.

### Почему транскрипт влезает целиком

Русская речь — примерно 8–9 тыс. слов в час, это ~16–20 тыс. токенов. Двухчасовая лекция ≈ 35–40
тыс. токенов, то есть **менее 5 % контекста в 1M**. Значит иерархическая свёртка (map-reduce) —
не основной режим, а фолбэк: свёртка по чанкам систематически теряет связь между вопросом в начале
и ответом в конце.

*(Оценка токенов на глаз; на этапе 2 замерить реальным счётчиком — русский текст токенизируется
хуже английского, и коэффициент надо знать, а не угадывать. Порог перехода на свёртку —
свойство провайдера в конфиге, а не константа в коде.)*

### Кэш префикса

У DeepSeek кэш контекста автоматический — совпал префикс, вход стоит $0.003 вместо $0.15 (в 50 раз
дешевле). У llama.cpp — свой prompt cache. Механизмы разные, правило одно и провайдеро-независимое:
**транскрипт идёт первым и байт в байт одинаково**, а всё изменчивое (профиль, вопрос, timestamp,
ID прогона) — после него. Тогда пересборка саммари в другом профиле или уточняющий вопрос по той
же записи почти бесплатны. Проверка, что кэш реально работает — поле usage в ответе, а не вера.

### Локальный режим

Второй класс по качеству, но обязательный: записи бывают такие, что транскрипт нельзя отдавать
наружу. Замер (#19, BENCHMARKS.md): Qwen3-4B-Instruct-2507 q4 через llama-server на встроенной
графике (Vulkan) — промпт ~75–110 токенов/с, генерация ~11 токенов/с, 4–5.4 ГБ общей памяти.
Трёхминутная лекция — 3 мин, двухчасовая — по расчёту ~20 мин окнами (#21): быстрее ASR.

Жёсткое правило: ASR-модель выгружена до загрузки LLM. 14 ГБ не прощают. Поэтому сервер — не
демон: его поднимает фабрика LLM после ASR и гасит оркестратор после саммари. KV-кэш префикса
переживает сервер на диске (слоты llama.cpp): повторный прогон той же записи не считает транскрипт
заново.

## Приватность

Локальный STT сам по себе приватности не даёт: **саммари по API увозит транскрипт целиком**.
Поэтому:

- флаг `--local-only` отключает любые сетевые провайдеры на уровне фабрики, а не уговорами:
  LLM с внешним адресом не создаётся, Whisper грузится только с диска (#20);
- перед первой отправкой наружу CLI показывает, что именно уедет (объём, провайдер) — один раз на
  хост провайдера, ответ хранится в SQLite (`consents`);
- аудио в сеть не уходит никогда — наружу может уйти только текст;
- в SQLite пишем, какая запись каким провайдером обработана: потом видно, что где побывало.
