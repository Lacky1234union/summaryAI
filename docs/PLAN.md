# План Summuraze

> Один этап = одна фокус-сессия. Следующий не начинаем, пока текущий не работает у пользователя.
> Архитектура и контракты — [`ARCHITECTURE.md`](ARCHITECTURE.md). Решения — [`DECISIONS.md`](DECISIONS.md).
> Открытые вопросы — [`QUESTIONS.md`](QUESTIONS.md). Замеры — [`BENCHMARKS.md`](BENCHMARKS.md).

## Цель

Запускаю `summuraze` — выбираю «записать» или «из файла» — получаю заметку в своём
Obsidian-хранилище, которую можно читать вместо записи: тезисы, структура, таймкоды, по клику
открывающие запись на нужной секунде. STT локально на CPU. Саммаризация — **переключаемая**:
DeepSeek по API или локальная модель, одним флагом.

**Интерфейсы — несколько, ядро одно** (решено 2026-10-26): подкоманды CLI для скриптов,
интерактивное меню для повседневного запуска (этап 2.5), веб-страница (этап 4). Все три вызывают
один и тот же конвейер и пишут в одно и то же место.

**Порядок по типам записей** (решено 2026-09-23): сначала **лекция с одним говорящим** —
это доводим до рабочего состояния. Многоголосые записи (созвоны, встречи, семинары с обсуждением)
— отдельный этап после, вместе с атрибуцией спикеров: без «кто сказал» саммари встречи почти
бесполезно, а с одним говорящим этот механизм не нужен вовсе.

**Критерий «готово» для продукта:** после двухчасовой лекции я читаю саммари и не пересматриваю
запись. Проверка — на реальных записях, не на синтетике.

## Этап 0 — Скелет и сквозной прогон

**Задача:** каркас, который прогоняет 2-минутный файл от начала до конца. Пусть саммари будет
одной строкой — важно, что стадии соединены и кэш работает.

- `pyproject.toml` (uv, Python 3.12 — **не 3.14**: проверить колёса `ctranslate2` и `torch` первым
  делом), `ruff` + `mypy` + `pytest`, `Makefile` с `lint`/`test`.
- `config.py` на pydantic-settings: единая точка валидации env, per-provider секции.
- `types.py` — контракты из ARCHITECTURE.md.
- `audio/ingest.py`: ffmpeg → wav 16 kHz mono; извлечение дорожки из видео; метаданные.
- `store/`: SQLite-схема задач + кэш артефактов на диске с ключами.
- `pipeline/orchestrator.py`: прогон стадий, кэш, прогресс в терминал.
- `cli.py`: `summuraze run <файл>`, echo-заглушки ASR и LLM.
- CI на Gitea Actions: `make lint` + тесты с покрытием (порог 85 %) на каждый PR; slow/eval
  в CI не гоняются. *(Добавлено 2026-10-23, #35: в исходном плане CI не было.)*

**Фикстуры.** Нужны 2–3 фрагмента по ~5 минут (лекция с терминами — приоритет) и reference-
транскрипты к ним. Транскрипты **не печатаем с нуля**: прогоняем самой большой моделью один раз,
дальше вычитываем и правим ошибки в текстовом виде. Это ~20–30 минут работы на 15 минут аудио
вместо нескольких часов. Без эталона WER мерить не на чем, а без WER выбор модели на этапе 1 —
угадывание.

**Приёмка:** `summuraze run fixtures/lecture_5min.mp4` проходит все стадии, второй запуск
мгновенный (кэш), CI на PR зелёный и обязателен для слияния в `dev`/`main`.

## Этап 1 — Локальный STT

**Задача:** выбрать модель **замером на этом железе** и получить транскрипт, которому можно верить.

Сначала бенчмарк, потом дефолт. Метрики: RTF (время обработки / длительность), WER против
reference, точность терминов и имён, пиковая RSS.

| Конфигурация | Зачем в таблице |
|---|---|
| faster-whisper `small` int8 | нижняя граница по качеству, верхняя по скорости |
| faster-whisper `medium` int8 | обычный компромисс |
| faster-whisper `large-v3-turbo` int8 | 4 слоя декодера — должен быть быстрее large-v3 в разы |
| faster-whisper `large-v3` int8 | скорее всего слишком медленно; замерить, чтобы знать цену |
| whisper.cpp `large-v3-turbo` Q5_K, CPU | другой рантайм, другая арифметика |
| whisper.cpp + Vulkan на Vega | единственный способ задействовать iGPU; может ускорить энкодер |

Дефолт выбираем по правилу: **лучшее качество при RTF ≤ 0.5** (час записи за ≤ 30 мин).
Результаты — в `BENCHMARKS.md` с датой и версиями.

- `audio/vad.py`: Silero VAD → интервалы речи, передаются в ASR.
- `asr/faster_whisper.py`: word-level таймкоды, `avg_logprob`, `no_speech_prob`.
- `asr/repetition.py`: детектор циклов Whisper (повтор n-граммы, аномальный logprob) — помечаем
  сегмент как сомнительный, а не молча оставляем «Спасибо за просмотр» в лекции.
- Словарь терминов курса (`--terms`): `hotwords` Whisper (≤ 60 токенов) + замены «слышится -> пишется»
  поверх кэша — дешёвый способ вытянуть жаргон и англицизмы лекции (ADR 2026-10-27).
- Вывод: `.json` (полный), `.txt`, `.srt` — транскрипт полезен и без саммари.

**Приёмка:** час лекции расшифровывается за приемлемое время, WER записан в BENCHMARKS.md,
на тишине и на музыке нет выдуманного текста.

## Этап 2 — Саммаризация: один адаптер, два пути

**Задача:** из транскрипта — документ, который читают вместо записи. И **переключение
локально ↔ API одним флагом** с самого начала, а не когда-нибудь потом.

Ключ к простоте: DeepSeek, OpenRouter, Yandex и локальный llama.cpp говорят по одному
OpenAI-совместимому протоколу. Значит один адаптер, а переключение — это `base_url` + `model`
(см. ARCHITECTURE.md, таблица режимов).

- `summarize/openai_compat.py` — единый адаптер. Дефолт: `deepseek-flash`, 1M контекста,
  **~$0.01 за двухчасовой документ**. `--local` переводит на llama.cpp server.
- `budget.py`: реальный подсчёт токенов; порог перехода на иерархию — свойство провайдера
  в конфиге, не константа.
- Стабильный префикс = транскрипт первым, байт в байт; профиль и вопрос после. У DeepSeek кэш
  автоматический (вход дешевеет в 50 раз), у llama.cpp свой prompt cache — механизмы разные,
  правило одно.
- `--local-only` режет сетевые провайдеры в фабрике, а не предупреждением в доках.
- Локальная модель: выбор замером, результат в BENCHMARKS.md. Правило: ASR-модель выгружена
  до загрузки LLM.

**Профили этого этапа — только однодневный случай:**

| Профиль | Структура документа |
|---|---|
| **Лекция** | TL;DR · глоссарий терминов · тезисы по разделам · формулы и примеры · что спросили в Q&A · что читать дальше · таймкоды разделов |
| **Сырой** | структурированный транскрипт с таймкодами, без интерпретации |

Профили созвона, встречи и семинара — этап 5, вместе со спикерами.

- `render/markdown.py` → **заметка Obsidian** — основной выход с этого этапа, а не экспорт из
  веба (решено 2026-10-26). Папка задаётся `SUMMURAZE_OUTPUT_DIR` (папка в хранилище). Заметка:
  frontmatter (дата, длительность, профиль, модели, стоимость, путь к записи), документ профиля,
  таймкоды — ссылки с `#t=<секунды>` для плагина **Media Extended**: клик открывает запись на этой
  секунде. Рядом `.srt` — Media Extended показывает его как интерактивный транскрипт.
  Любое утверждение проверяется за две секунды.
- Учёт стоимости и времени каждого прогона — в SQLite, видно в `summuraze log`.

**Приёмка:** на реальной лекции заметка появляется в Obsidian, читается как документ, таймкоды
открывают запись на нужной секунде; `--local` и API дают сопоставимый
по структуре результат (качество разное — это нормально, оно в BENCHMARKS.md); повторный
`summarize` не перезапускает ASR.

## Этап 2.5 — Меню и запись лекций

**Задача:** пользоваться без знания подкоманд и без внешних программ записи. Добавлено
2026-10-26: в исходном плане запись была только на этапе 6, а меню не было вовсе.

- `summuraze` без аргументов → меню (#38): **записать** / **из файла** / **последние заметки**
  (открыть в Obsidian) / настройки (провайдер, папка вывода). Подкоманды остаются для скриптов.
- `audio/record.py` + `summuraze record` (#37): PipeWire, микрофон и звук системы — **сразу двумя
  дорожками** в одном файле (ADR «Раздельные дорожки при записи»: потом файл уже не разделить).
  Для лекции ингест сводит дорожки (ADR #5); на этапе 6 эти же файлы дают атрибуцию спикеров.
  Старт/стоп, уровень сигнала, авто-стоп по тишине; по стопу — конвейер без ручных шагов.

**Приёмка:** онлайн-лекция записана из меню одной командой, по стопу заметка появилась
в Obsidian.

## Этап 3 — Длинные записи и защита от вымысла

**Задача:** не разваливаться на четырёхчасовом материале и не сочинять.

- `windows.py`: нарезка по границам фраз с перекрытием ~10 %, никогда не посреди предложения.
- Двухпроходная схема для длинного: проход 1 — карта разделов с таймкодами; проход 2 — финальный
  документ по карте + полный транскрипт. Модель видит структуру целиком до того, как пишет текст.
- `verify.py`: отдельный проход — каждый вывод должен иметь таймкод и подтверждаться транскриптом.
  Неподтверждённое **помечается, а не удаляется**: «модель это придумала» — тоже информация.
- Сегменты, помеченные на этапе 1 как сомнительные, доходят до промпта как «здесь плохо слышно» —
  модель не должна достраивать смысл по битому тексту.

**Приёмка:** четырёхчасовая запись обрабатывается; проверка 20 случайных утверждений из саммари
по таймкодам — без выдуманных фактов.

## Этап 4 — Интерфейс

**Задача:** третий интерфейс к тому же ядру — для тех случаев, когда удобнее браузер: плеер
рядом с транскриптом, очередь задач, запуск с другого устройства в сети. Меню (этап 2.5) и
Obsidian (этап 2) он не заменяет.

- FastAPI + одна страница: список записей, статус, просмотр транскрипта с плеером — клик по строке
  прыгает на таймкод.
- Правка саммари руками с сохранением (модель ошибается, документ остаётся).
- Переключатель провайдера в UI, с показом цены прогона.
- Экспорт: скачать `.md`, буфер обмена. Запись в Obsidian уже есть с этапа 2 — веб пишет туда же.
- Watch-папка: файл упал → задача в очередь, готовое саммари — уведомлением.

**Приёмка:** запись кидается через браузер, документ читается там же, правки сохраняются.

## Этап 5 — Многоголосые записи: созвоны, встречи, семинары

**Задача:** «кто сказал» и профили под обсуждение. До этого этапа система про один голос.

- `speakers/diarizer.py` — diarization-модель для «много людей в одной комнате». На CPU это дорого:
  сравнить варианты по RTF и DER, результат в BENCHMARKS.md. Если тяжёлый вариант неприемлем по
  времени — остаётся только путь с раздельными дорожками (этап 6).
- Сопоставление имён: модель предлагает имена по содержанию («меня зовут…», обращения),
  пользователь подтверждает; сопоставление запоминается между записями.
- Новые профили:

| Профиль | Структура документа |
|---|---|
| **Созвон / встреча** | TL;DR 3–5 строк · участники · принятые решения · действия (кто / что / срок) · открытые вопросы · спорные места с цитатами · таймкод-навигация |
| **Семинар** | разобранные задачи · выводы · домашнее задание · кто что обещал |

- Автодетекция профиля дешёвой моделью как подсказка, финальное слово — флаг `--profile`.

**Приёмка:** на встрече с 3+ участниками реплики атрибутированы, действия привязаны к людям,
а не к «Speaker 2».

## Этап 6 — Созвоны по раздельным дорожкам

**Задача:** точная атрибуция «я / собеседники» бесплатно, без diarization-модели.

- Запись уже есть с этапа 2.5 и с самого начала пишет микрофон и монитор вывода раздельными
  дорожками. Здесь — `speakers/tracks.py`: `SpeakerSource` по дорожкам (`--stream` в ингесте,
  ASR по каждой, склейка по времени). Покрывает типичный созвон «я и остальные».
- Пункт меню «записать созвон» → профиль «созвон/встреча» с атрибуцией по дорожкам.

**Приёмка:** созвон записан одной командой, дорожки раздельные, саммари появилось без ручных шагов.

## Guardrails

Мнемоника: **провайдер за протоколом, конфиг типизирован, стадия кэширована, утверждение с
таймкодом, локально — значит локально, гейт зелёный.**

| # | Правило | Почему |
|---|---|---|
| 1 | Провайдер — за Protocol + фабрика по конфигу; вендорский импорт только внутри адаптера, лениво | смена STT или LLM не должна трогать конвейер; CLI стартует быстро |
| 2 | Переключение локально ↔ API — это конфиг (`base_url`/`model`), а не ветка в коде конвейера | требование пользователя; оба пути обязаны работать всегда, а не «локальный когда-нибудь» |
| 3 | Конфиг типизирован (pydantic-settings), без `os.getenv` вразброс | неизвестная переменная падает на старте, а не посреди часовой транскрибации |
| 4 | Каждая стадия кэшируется на диск, ключ включает версию стадии и параметры | ASR — дорогая стадия; правка промпта её не перезапускает |
| 5 | Любое утверждение в саммари привязано к таймкоду | единственная реальная защита от вымысла — проверяемость |
| 6 | Порог: без GPU, без k8s, без fine-tune; всё работает на одном ноуте | железо известно (см. ARCHITECTURE.md) |
| 7 | `--local-only` запрещает сеть на уровне фабрики | «локальный STT» ≠ приватность: саммари по API увозит транскрипт |
| 8 | Модель выбирается замером на этом железе, результат — в BENCHMARKS.md с датой | чужие бенчмарки на 4090 здесь не значат ничего |
| 9 | ID моделей провайдера сверяются в момент реализации | `deepseek-chat` retired 24.07.2026 — модельный ряд меняется чаще, чем доки |
| 10 | `make lint` + `make test` — зелёные перед коммитом; CI обязателен для слияния | |

## Чего в плане сознательно нет

- **Realtime-транскрибация** — на этом CPU либо мелкая модель с плохим качеством, либо отставание.
  Возможна как отдельная фича с явным выбором модели, но не как режим по умолчанию.
- **Интеграции с Zoom/Meet/Teams по API** — запись монитора вывода (этап 2.5) работает с любым
  источником и не требует ничьих разрешений.
- **Fine-tune STT под свои термины** — сначала исчерпать дешёвое: `initial_prompt` со словарём
  и постобработка частых ошибок.
- **Claude как дефолт** — тот же 1M контекста стоит в 30 раз дороже DeepSeek. Адаптер завести
  недорого, если понадобится сравнить качество; дефолтом он не станет.
- **Мультиязычность сверх RU/EN** — пока не нужна; в контрактах язык уже параметр.
